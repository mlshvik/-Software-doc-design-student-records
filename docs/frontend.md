# Клієнтська частина (React)

Односторінковий застосунок (SPA) на **React 19 + TypeScript**, збирається **Vite**. Залежностей
мінімум: лише `react` і `react-dom`. Маршрутизацію, роботу з API та діаграми реалізовано власними
невеликими модулями, без сторонніх бібліотек.

## Запуск

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173, запити /api проксіюються на http://localhost:8080
npm run build      # перевірка типів (tsc) + продакшн-збірка в dist/
```

Адресу бекенду для режиму розробки можна змінити змінною `VITE_API_TARGET`.

## Структура

```
frontend/src
├── api/
│   ├── client.ts        – обгортка над fetch: JWT у заголовку, помилки RFC 7807 → ApiError
│   └── types.ts         – типи DTO бекенду
├── auth/AuthContext.tsx – вхід/вихід, відновлення сесії за збереженим токеном, роль користувача
├── router.tsx           – мінімальний маршрутизатор на History API (шаблони шляхів з параметрами)
├── components/
│   ├── Layout.tsx       – бічне меню за роллю, верхня панель, лічильник сповіщень
│   ├── ScheduleGrid.tsx – сітка розкладу «дні × пари» з чисельником/знаменником
│   ├── ReportView.tsx   – відображення звітів бекенду: підсумки, діаграма, таблиця
│   ├── BarChart.tsx     – стовпчикова діаграма на SVG
│   ├── CrudPage.tsx     – узагальнена сторінка довідника (таблиця + форма + видалення)
│   ├── FormFields.tsx   – генератор полів форми з помилками валідації
│   ├── Modal.tsx        – модальне вікно і діалог підтвердження
│   └── ui.tsx           – картки, статистика, бейджі ЄКТС, завантаження, помилки
├── pages/
│   ├── LoginPage.tsx, NotificationsPage.tsx, NotFoundPage.tsx
│   ├── student/         – кабінет студента
│   ├── teacher/         – кабінет викладача
│   └── admin/           – адмін-панель (довідники, студенти, розклад, звіти, налаштування)
└── utils/               – форматування, словники назв, хук useApi
```

## Кабінет студента

| Сторінка | Що показує | API |
|---|---|---|
| Мій кабінет | середній бал і ЄКТС, кількість боргів, статус, заняття на сьогодні, останні оцінки | `GET /students/{id}/record` (Facade) |
| Оцінки | оцінки за семестрами: контроль, кредити, спроба, бал, національна шкала, ЄКТС; непідсумкові спроби приглушено | те саме |
| Розклад | сітка на тиждень, чисельник/знаменник | те саме |
| Заборгованості | відкриті й закриті борги | те саме |
| Сповіщення | нові оцінки, відкриття/закриття боргів; позначення прочитаними | `/notifications/me` |

Уся картка студента завантажується **одним запитом** до фасаду `StudentRecordFacade`.

## Кабінет викладача

| Сторінка | Що показує | API |
|---|---|---|
| Мої дисципліни | призначення викладача за роками й семестрами | `GET /assignments` |
| Відомість | студенти групи, усі спроби, підсумок, ЄКТС, поле для наступної дозволеної спроби | `GET /assignments/{id}/sheet`, `POST /grades` |
| Розклад | заняття викладача | `GET /schedule/me` |
| Статистика | звіт «Статистика оцінювання по викладачах» із діаграмою; власний рядок підсвічено | `GET /reports/teacher-statistics` |

У відомості спершу виконується швидка перевірка діапазону 0–100 у браузері, а остаточні правила
(статус студента, власник дисципліни, ліміт перескладань) перевіряє бекенд ланцюжком
**Chain of Responsibility**. Повідомлення про помилку показується в рядку студента.
Після збереження оцінки бекенд (**Observer**) відкриває або закриває заборгованість і надсилає
студенту сповіщення, тому відомість одразу пропонує наступну спробу (перескладання → комісія).

## Адмін-панель

| Розділ | Можливості | API |
|---|---|---|
| Огляд | кількість студентів, викладачів, груп, відкритих боргів; звіт успішності з діаграмою | кілька запитів паралельно |
| Студенти | пошук за ПІБ / заліковою (із затримкою введення), фільтри за групою, курсом, статусом; створення, редагування, видалення; картка студента | `/students` |
| Зміна статусу | діалог пропонує лише дозволені переходи (дзеркало шаблону **State**); остаточне рішення – на сервері | `PATCH /students/{id}/status` |
| Викладачі, групи, дисципліни, спеціальності, факультети, призначення | однаковий інтерфейс довідника: таблиця з пошуком, форма в модальному вікні, видалення з підтвердженням | `/teachers`, `/groups`, … |
| Розклад | конструктор розкладу групи: форма заняття з перевіркою конфліктів **під час введення**, сітка з видаленням занять | `/schedule`, `POST /schedule/check` |
| Заборгованості | відкриті / закриті борги з фільтром за групою | `/debts` |
| Звіти | вкладки трьох звітів, фільтри (рік, семестр, курс, факультет), діаграма, таблиця, підсумки, друк | `/reports`, `/reports/{slug}` |
| Налаштування | спосіб розрахунку середнього балу (**Strategy**) та інші параметри | `/settings` |

Довідники побудовано на одному узагальненому компоненті `CrudPage<T>`: кожна сторінка – лише
конфігурація (колонки таблиці, поля форми, перетворення «форма ↔ запит»). Помилки валідації сервера
(`errors` у Problem Details) показуються біля відповідних полів, а конфлікти цілісності (409, напр.
видалення факультету зі спеціальностями) – повідомленням над таблицею.

## Безпека на клієнті

- Токен зберігається в `localStorage` і додається до кожного запиту (`Authorization: Bearer …`).
- Відповідь `401` (прострочений токен) автоматично розлогінює користувача.
- Набір маршрутів залежить від ролі; сторінки інших ролей недоступні (404). Остаточне розмежування
  доступу виконує бекенд.
